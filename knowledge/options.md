# Варианты и сильные возражения

## Что значит «содержательно разные»
Варианты отличаются хотя бы по одной оси — иначе это один вариант с настройками:
- **кому** помогаем (семьи / владельцы нескольких номеров / новые клиенты);
- **какую проблему** решаем (перебой интернета / неоплата / непонятное списание / привлечение);
- **механизм** (сигнал в существующем приложении / изменение тарифа / новый кабинет / партнёрство / отказ);
- **объём и обратимость** (неделя работы и откат кнопкой / квартал разработки / изменение биллинга).

Обязательно включи:
- **«Оставить как есть»** — что будет при продолжении нынешнего обслуживания (обычно это прогноз «без изменений»).
- **«Закрыть / заморозить направление»** — если уместно: что освободится (люди, деньги) и что потеряем.
- Хотя бы один вариант, который ты **всерьёз мог бы рекомендовать** вместо основного.

## Карточка варианта

| Поле | Содержание |
|---|---|
| Суть | Одно предложение: кому, что меняем, каким механизмом |
| Клиентская ситуация | Один и тот же случай и горизонт для всех вариантов |
| Польза | Что выигрывает клиент; метрика пользы |
| Охват | Скольким клиентам доступно (база, доля, расчёт) |
| Затраты | Чел.-месяцы по ролям, зависимости от других команд |
| Срок первых результатов | Когда увидим сигнал |
| Деньги | Вклад в валовую прибыль (диапазон), граница решения |
| Последствия ошибки | Что сломается, как откатить |
| Сильнейшее возражение | От `red-team`: самый неудобный аргумент против |
| Ответ на возражение | Чем снимаем или какое наблюдение покажет, что возражение верно |
| Тип утверждений | Ссылки на C-… (факты отдельно от допущений и прогнозов) |

## Сравнительная таблица
Сравнивай варианты по одной клиентской ситуации и одному горизонту: польза, число клиентов, затраты, срок, риск,
обратимость. Если более дешёвый вариант даёт почти ту же пользу — укажи, **какое наблюдение оправдает переход
к дорогому**. Если ни один нельзя обоснованно выбрать для широкого запуска — предложи **самую короткую проверку,
которая изменит решение**.

## Как писать сильное возражение
Слабое: «может не сработать». Сильное — конкретное, проверяемое и бьёт в главное допущение:
- «Перебои по нехватке пакета могут быть редки: если 70 % ограничений — из-за неоплаты, сигнал об остатке решает
  меньшинство случаев, а разработка уйдёт не туда.»
- «Организатор, получив сигнал, всё равно может не выделить интернет: свободного остатка может не быть в конце месяца.»
- «Рост активности за счёт просмотров сигнала — это рост метрики, а не пользы: человек открыл push, но связь не сохранилась.»

Возражения формирует субагент `red-team` (сильная модель) без доступа к твоей рекомендации — он видит только варианты.
