# Шаг 10 — Итоговый документ

1. `./sfp stage 10_deliverable in_progress`
2. Структура — по требованиям заказчика (если бриф задаёт части — следуй им). По умолчанию:
   0. Резюме на 1 экран: первые клиенты, проблема, предложение, ожидаемый результат, просьба.
   1. Клиент и проблема · 2. Предложение и путь к клиенту (продукт + коммуникация) · 3. Польза и прибыль, план проверки ·
   4. Варианты, выбор и план по кварталам · 5. Ресурсы, риски, решение руководителя ·
   Приложения: реестр ключевых утверждений (тип/источник), расчёты, пробелы, журнал и стоимость.
3. Пиши из `work/`, не придумывай нового. Каждое число — со ссылкой [C-…]. Факты/допущения/прогнозы различимы
   (пометки «факт», «допущение», «прогноз» или таблица типов).
4. `./sfp check` — 0 ошибок. `evaluator` по полной рубрике (`eval/rubric.md`). < 0,75 → доработка.
5. Экспорт: `./sfp export` (HTML рядом с md).
6. Контрольная точка: `./sfp stage 10_deliverable waiting_human --note "принять или исправить документ"`. **Остановись.**
7. Правки руководителя → внеси, перепроверь; `./sfp stage 10_deliverable done --next "Шаг 11: реестр решений"`
