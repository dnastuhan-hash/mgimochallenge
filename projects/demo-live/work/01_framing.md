# 01. Постановка задачи — demo-live

Запрос: «Направление семейных групп отстаёт от плана: активных групп 4 000 вместо 5 000 [C-001]. Почему, и что делать в следующем году?»
Источник: бриф [S-001].

## Карточка постановки

| Поле | Содержание |
|---|---|
| Вопрос (через проблему, не решение) | Какая часть отставания по активным группам объясняется **притоком** групп, **активацией** (приглашение → первое действие) и **уходом** подключённых групп — и какое изменение в следующем году сильнее всего сократит разрыв до цели при доступных ресурсах |
| Решение 1 и срок | Конец Q1 планового года: выделять ли людей и деньги на пилот (и какой) — руководитель направления [C-006] |
| Решение 2 и срок | Конец Q2: вместе с финансовой командой — расширять охват, менять предложение или продолжать наблюдение [C-006] |
| Получатель и критерий | Руководитель направления (обоснованность причины, обратимость пилота) + финансовая команда (вклад в валовую прибыль, окупаемость) |
| Цель и метрики | Плановый год: активных групп за последний месяц ≥ 8 000 (без изменений 5 000); подключённых ≥ 12 000 (без изменений 8 000); активация за 14 дней ≥ 60 % (без изменений 45 %); валовая прибыль ≥ 285 млн руб. (без изменений 279) [C-004, C-005] |
| Масштаб отставания (первичная раскладка) | 4 000 активных = 6 500 подключённых × ≈ 62 % активных; по плану 7 500 × ≈ 67 %. Примерно ⅔ разрыва — меньше подключённых групп, ⅓ — ниже доля активных [C-009, C-010]. Внутри «меньше подключённых» не различаем: мало создали, не приняли приглашение или ушли — это главный пробел |
| Ограничения | Q2: 3 чел.-мес. разработки (предварительно); дизайнер и аналитик по 0,5 ставки не выделены; тестирование 1 чел.-мес. не подтверждено [C-007]. Только открытые данные и материалы пользователя. Согласие участника и права плательщика — обязательные условия любого сценария [S-001] |
| Доступные данные | Бриф с показателями базового и планового года, определениями активности/активации/подключения, учебной ставкой 500 руб. за доп. оплаченный месяц [S-001] |
| Известные пробелы | Нет воронки «создана → приглашение принято → первое действие» по месяцам; нет оттока групп и номеров; нет учёта обращений в поддержку по причинам; нет разбивки по каналам привлечения и тарифам; нет историй клиентов [C-008] |
| Горизонт | Плановый год по кварталам + измеримый ориентир на конец 3-го года |
| Вне рамок | Ценообразование тарифов целиком; полноценная стратегия для владельцев нескольких номеров (по ним — прогноз «без изменений» и последствия, если не решим иначе) |

## Допущения постановки
- Отвечаем на вопрос о **семейных группах**; владельцы нескольких номеров — вторая группа, только прогноз и последствия (уточняется вопросом 2).
- Числа брифа учебные и считаются достоверными для задачи.

## Вопросы руководителю (каждый меняет следующий шаг)

1. **Есть ли данные помимо брифа?** (воронка по этапам, отток групп, обращения в поддержку, разбивка по тарифам/каналам)
   — *Да* → шаг 02 начинаем с их регистрации, причины считаем по данным. *Нет* → причины формулируем как гипотезы с диапазонами и планом их проверки в Q1.
   **По умолчанию:** нет, работаем по брифу.
2. **Рамка: только семьи или семьи + владельцы нескольких номеров?**
   — *Только семьи* → варианты и пилот только для групп. *Обе* → отдельный расчёт и сценарий для владельцев.
   **По умолчанию:** фокус на семьях, по владельцам — прогноз «без изменений» и цена бездействия.
3. **Использовать ли материалы прошлого проекта `family-connect`?**
   — *Только источники* → переиспользую зарегистрированные документы, выводы делаю заново. *Ничего* → чистый старт. *Источники и выводы* → быстрее, но прежние выводы — не факты, их придётся перепроверить.
   **По умолчанию:** только источники; выводы прошлого проекта — не основание.
4. **Можно ли подтягивать открытые веб-источники** (например, публичную статистику по семейным тарифам)?
   — *Да* → перед каждым доменом даю обоснование и прошу согласия. *Нет* → только бриф.
   **По умолчанию:** нет; предложу конкретные домены, только если вопрос без них не закрыть.
