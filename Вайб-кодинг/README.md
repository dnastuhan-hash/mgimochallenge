# Деканат Next — концепт личного кабинета студента

> **Концепт для конкурса «Цифровой деканат будущего».** Это не официальный сервис вуза. Все ФИО, оценки, номера и контакты вымышлены. Прототип не подключается к реальным системам вузов.

Кабинет, где всё учебное собрано в одном месте и **настраивается под студента**: лишние разделы можно скрыть, нужные закрепить в нижнем меню. Расписание подписывается в Google или Яндекс Календарь, тесты из СДО не теряются.

## Открыть без установки

**Демо-версия: https://dnastuhan-hash.github.io/mgimochallenge/** — открывается в любом браузере, в том числе с телефона.

В демо-версии «сервер» кабинета работает прямо в браузере: тот же код из `server/routes.js`, `logic.js`, `schema.js` на SQLite, скомпилированном в WebAssembly ([sql.js](https://github.com/sql-js/sql.js), MIT). Данные хранятся только в браузере проверяющего, на странице входа их можно сбросить к исходным. Подписка на календарь в демо недоступна, потому что нужен сервер, но файл `.ics` скачивается.

> Демо-версия нужна для просмотра. **Настоящая защита** (HttpOnly-cookie, scrypt на сервере, разделение данных на стороне сервера) работает в серверной версии: `npm start`. Её проверяют автотесты `npm test`.

Сборка демо: `npm run build:demo` (папка `dist-demo/`), локальная проверка: `npm run serve:demo`.

## Что умеет

**Обязательное ядро**
- **Вход и профиль**: логин и пароль, ФИО, институт, направление, курс, группа, основа обучения.
- **Расписание**: день и неделя, числитель и знаменатель, «следующая пара через N мин», переносы, отмены и замены выделены цветом, вкладка «Сессия».
- **Успеваемость**: баллы текущего семестра с детализацией, прогноз оценки, «до четвёрки не хватает N б.», допуск, зачётная книжка, средняя оценка, долги.
- **Справки и заявки**: 9 типов, форма из 1–3 полей (ФИО и группа подставляются сами), трекер статуса «Принята → В работе → Готово → Получено», отмена.
- **Уведомления**: переносы, статусы заявок, сроки тестов, объявления. Важные нельзя отключить, новости и события можно.

**Идеи сверх ТЗ**
- **Модульный кабинет.** При первом входе студент выбирает набор «Минимум», «Стандарт» или «Всё». Потом разделы можно скрывать, менять местами и закреплять в нижнем меню. Набор по умолчанию зависит от профиля: бюджетнику показывается стипендия, контрактнику оплата, жильцу общежития раздел общежития, первокурснику карта.
- **Расписание в любом календаре** по стандарту iCalendar. Подписка в Google, Яндекс или Apple обновляется сама при переносах. Ссылку можно сбросить. Дедлайны в календарь не выгружаются.
- **Тесты СДО**: открытые, скоро и завершённые, таймер до закрытия, прямая ссылка, напоминания (интервалы настраиваются), виджет «Горит» на главной. Подключение через адаптеры (Moodle и др.). Если СДО не подключена, тест вручную добавляет сотрудник.
- **Стипендия**: дата и сумма ближайшей выплаты, прогноз «сохранится ли» по текущим баллам и какие предметы подтянуть.
- **Цифровой студбилет**: QR подписан сервером (HMAC) и действует 5 минут, поэтому скриншот не сработает. Страница проверки показывает минимум данных.
- **Карта кампуса**: поиск аудитории («Б-201» → корпус Б, 2 этаж). Аудитории в расписании кликабельны.
- **Чат с деканатом**, **помощник** (ответы по базе знаний и данным студента, без внешних ИИ-ключей), **поиск по кабинету** (находит и скрытые разделы), **общежитие**, **поддержка**, **тёмная тема**.

## Запуск локально

Нужен Node.js 22.13+ (используются встроенные `node:sqlite` и `crypto.scrypt`).

```bash
npm install
npm start            # http://localhost:3000; при первом запуске база заполняется демо-данными
npm test             # автотесты безопасности
node server/index.js --reset   # пересоздать базу с демо-данными
```

## Деплой (доступ из России без VPN)

В проекте есть `Dockerfile` и `amvera.yml`. Они лежат в папке `Вайб-кодинг/`: собирайте образ из неё, а на хостинге указывайте её как корень проекта (или загрузите содержимое папки как отдельный проект). Подойдёт любой хостинг с Docker и постоянным диском:

1. **Amvera Cloud** (amvera.ru): создать проект, подключить репозиторий или загрузить код. Конфиг `amvera.yml` уже есть, данные хранятся в `/data`.
2. **Timeweb Cloud / Yandex Cloud / VPS**: `docker build -t dekanat . && docker run -d -p 80:3000 -v dekanat-data:/data dekanat`.

Переменные окружения (все необязательные):
- `PORT` — порт (по умолчанию 3000);
- `DATA_DIR` — папка для базы (по умолчанию `./data`);
- `PUBLIC_URL` — внешний адрес для календарных ссылок, например `https://dekanat.example.ru`;
- `APP_SECRET` — секрет подписи QR. Если не задан, генерируется в `DATA_DIR`.

> Для подписки на календарь сайт должен работать по HTTPS: Google и Яндекс не читают `http://localhost`.

## Как устроено

```
server/            Node.js без фреймворков
  index.js         адаптер Node.js: cookie, CSRF, заголовки безопасности, статика
  routes.js        все маршруты API и проверки доступа (общие для сервера и демо)
  schema.js        схема БД и вымышленные демо-данные (общие)
  auth.js          scrypt-хеши паролей, токены сессий, ограничение попыток входа
  db.js            открытие SQLite в Node.js
  logic.js         расписание, оценки, стипендия, тесты СДО (адаптеры), уведомления, помощник
  ics.js           экспорт расписания в iCalendar и список календарей-провайдеров
  time.js          даты по Москве, относительные даты для «живого» демо
public/            SPA на чистом JS (без сборки)
  core.js          шаблоны с автоэкранированием, API-клиент, разделы и персонализация, роутер
  student.js       страницы студента
  staff.js         кабинет сотрудника
  styles.css       дизайн-токены, светлая и тёмная темы, mobile-first от 360px
demo/              «сервер в браузере» для GitHub Pages, сборка и локальная проверка демо
tests/             автотесты безопасности (node:test)
docs/              исследование и описание процесса для жюри
```

**Масштабирование.** Сервер не хранит состояние между запросами: сессии лежат в БД, поэтому можно запустить несколько экземпляров. Для большого вуза SQLite меняется на PostgreSQL: запросы на чистом SQL, а адаптеры СДО и календарей вынесены в отдельные модули.

## Безопасность

- Пароли хранятся только как **scrypt**-хеш с солью. Токен сессии в базе хранится как SHA-256.
- Сессия передаётся в cookie `HttpOnly; SameSite=Strict` (плюс `Secure` по HTTPS), JavaScript страницы к ней доступа не имеет.
- **Каждый запрос фильтруется по пользователю из сессии**: чужую заявку не открыть, даже подставив номер в адрес. Ответ `404` одинаков для «нет такой» и «чужая», поэтому перебирать номера бесполезно.
- Роли разделены: студент получает `403` на API сотрудника, сотрудник — на студенческое API.
- Защита от CSRF: изменяющие запросы принимаются только со специальным заголовком и с того же Origin.
- Строгий Content-Security-Policy, все данные в интерфейсе экранируются (защита от XSS).
- Ограничение попыток входа: 8 за 5 минут. Время ответа не выдаёт, существует ли логин.
- Секреты не лежат в коде и в браузере: секрет QR берётся из переменной окружения или файла на сервере. Внешних ИИ-ключей нет.
- Всё это проверяют автотесты в `tests/security.test.js` (`npm test`).
