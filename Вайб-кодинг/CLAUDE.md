# CLAUDE.md — инструкция для ИИ-агентов, работающих с проектом

Проект: «Деканат Next», концепт личного кабинета студента для конкурса. Продуктовые решения и данные исследования лежат в `docs/RESEARCH.md`. Прочитай его прежде, чем добавлять функции.

## Жёсткие правила
1. **Только вымышленные данные.** Не добавляй реальные ФИО, вузы, логотипы, телефоны и логины. Домены — `*.example`.
2. **На каждом экране должна быть пометка «концепт для конкурса, не официальный сервис»**: в каркасе (`renderShell`) и на странице входа.
3. **Безопасность не ослаблять:**
   - любой SQL-запрос к данным студента содержит `user_id = ?` из сессии (`ctx.user`), а не из параметров запроса;
   - для чужого или несуществующего объекта возвращай одинаковый `404`;
   - новые изменяющие маршруты получают CSRF-проверку автоматически (заголовок `X-Requested-With: dekanat`);
   - в HTML вставляй только через тег `html\`...\`` из `public/core.js`: он экранирует. `raw()` используй только для своих строк, не для данных;
   - секреты брать только из переменных окружения, в репозиторий и в браузер их не класть.
4. **Без зависимостей без нужды.** Сервер работает на `node:http` + `node:sqlite`, фронтенд — на чистом JS без сборки. Новую библиотеку добавляй только с разрешающей лицензией и записывай её в README.
5. **Mobile-first.** Всё должно работать на ширине 360 px без горизонтальной прокрутки. У элементов сетки ставь `min-width: 0`.
6. **Сроки тестов и дедлайны в календарь (ICS) не выгружаются.** Это решение команды: в календарь идут только занятия и сессия.

## Как устроено
- `server/logic.js`: предметная логика. Новые источники СДО добавляются в `lmsAdapters`, новые календари — в `CALENDAR_PROVIDERS` (`server/ics.js`).
- Разделы кабинета описаны в `SECTIONS` (`public/core.js`). Новый раздел = запись в `SECTIONS` + id в `SECTION_IDS` (`server/index.js`) + страница `page(/^\/id$/, ...)` в `student.js`. Видимость проверяется через `isVisible(id)`, а виджеты главной показываются только для видимых разделов.
- Демо-даты относительные (`d+1@20:00`, `next:N`), поэтому прототип выглядит «живым» в любой день проверки.

## Проверка перед сдачей
- `npm test`: автотесты безопасности должны проходить все.
- Пройти сценарии в браузере на 360 px: вход → онбординг → главная → расписание → оценки → заказ справки → её статус. Затем вход за сотрудника → смена статуса → у студента появилось уведомление.
- `node --check` для всех изменённых JS-файлов.
